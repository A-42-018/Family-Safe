## Decisions locked in Phase 8
- **One new migration** `…000900_enrollment.sql` with three atomic SQL functions (`SECURITY DEFINER`, `search_path=''`, `EXECUTE` for `service_role` only): `enrollment_create_token(parent, child, token_hash, ttl)`, `enrollment_redeem(token_hash, device info…, refresh_hash, refresh_ttl)`, `enrollment_revoke_device(parent, device, ip)`. Ownership and single-use are decided **in the database**; Edge Functions authenticate first, then call them with the service role (`supabase.rpc`, bytea as `\x…` hex). No dependency changes, no table changes.
- **Pairing code (decision made this phase):** 16 Crockford-base32 symbols = 80 bits from the CSPRNG (`byte & 31`, unbiased), shown as `XXXX-XXXX-XXXX-XXXX`, TTL **10 min**, **one live code per child** (minting replaces the previous unconsumed one). Same value is the QR payload `familysafe://enroll?c=<code>`. The earlier idea of an 8-char code + longer QR secret was dropped: a short code is only brute-force-resistant with rate limits, and the in-memory limiter is per-isolate until Phase 31. Stored hash = `HMAC-SHA256(PAIRING_TOKEN_PEPPER, normalized code)`; the code is never stored, logged or echoed. `pairing_tokens.failed_attempts` stays unused (a wrong guess matches no row) — limiting is per IP at the Edge.
- **Functions (all `verify_jwt=false` at the gateway):** `enrollment-create` (parent JWT via `requireParent`; `{child_id}` strict; 201 with code/QR payload/expiry; foreign ≙ missing ≙ 404; limits 30/5 min/IP pre-auth + 10/15 min/parent), `enrollment-redeem` (**unauthenticated**, `Authorization` never read; strict body, no `child_id`/status/ids from the device; unknown/expired/replayed → identical `401 Invalid or expired pairing code`; 5 attempts/5 min/IP, every attempt counts, so a locked IP is refused even with the right code; deliberately no global limiter — it would allow denial of enrollment), `device-revoke` (parent JWT; idempotent; 404 for foreign ≙ missing; 20/5 min/parent). Contracts in `packages/contracts/src/enrollment.ts` mirrored in `_shared/enrollment.ts` (a contracts test reads the Edge file and fails on drift). `normalizeIp` moved to `_shared/ip.ts` (re-exported by `auth-events`).
- **Redeem result:** device row `ENROLLED` (rules OFF/permissions NOT_REQUESTED via existing trigger), one live refresh credential (SHA-256 stored, 30-day TTL), `DEVICE_ENROLLED` audit row for the parent who minted the code. **No IP stored** in that audit row (a child's network address would leak location that is opt-in elsewhere). Response: `device_id`, HS256 device JWT (15 min; `sub`=device id, `cid`=credential id, `jti`), opaque 256-bit refresh token + expiry. FCM token registration is **not** part of redeem (Phase 10/20).
- **Revoke:** device `REVOKED`/`OFFLINE`, all credentials `revoked_at`, `device_tokens` row deleted, `DEVICE_REMOVED` audit (`reason:"revoked"`, parent IP). Row + history stay (hard removal → Phase 32). Re-enrolling a phone = new device row. Known gap until Phase 11: an access JWT issued before revocation stays valid ≤ 15 min (`cid` not yet checked on device requests). Pending commands are not touched; Phase 20 must refuse revoked devices.
- **Web:** Server Actions `createPairingCodeAction` / `revokeDeviceAction` (`lib/enrollment/{service,actions,queries,format,state}.ts`) forward the parent's own access token (after `auth.getUser()`) to the Edge Functions from the Next server; logs contain HTTP status only; generic error mapping (401/403 → sign-in, 404 → not found, 429 → too many). UI on `/children/[id]` (P7 page): **Add device** native-`<dialog>` (code in component state only, remounted/dropped on close, "stays visible… child confirms" copy), device list (status badge, subtitle, last seen) with **Revoke access** via the shared `DeleteDialog` (now takes `confirmValue`/`pendingLabel`; token `confirm=revoke`). Device queries select no credential/push columns. **No QR image yet** (typed code only; payload is returned) and `/devices` index stays a stub — both deferred.
- **Verified with the real toolchain this time:** PostgreSQL 16 + pgTAP **245** tests (58 new: privileges, ownership, TTL bounds, re-mint replaces, redeem happy path/replay/unknown/expired/rollback/duplicate-hash, revoke idempotency + audit, family B untouched); a 12-way parallel redeem on real PG → exactly 1 device; Deno **71** tests (+38: crypto helpers incl. RFC HMAC vector and bias check, all three handlers incl. concurrency with a fake atomic store, lockout, header-ignored, log-leak, sanitized 500s, CORS); `deno check` on all 5 entrypoints; contracts **86** (+26); web **275** (+50: service with fakes, queries, format, structural guards); `tsc --noEmit`, ESLint (0 warnings), `next build`, `check:structure`, `check:secrets` (source + build output) green. **Not run:** the Edge Functions against a live `supabase functions serve` (no Docker) — in particular supabase-js `rpc()` with `\x` hex bytea params and the `o_*` result mapping are covered only by fakes and equivalent `psql` calls; Server Actions → Edge and the dialogs in a real browser (375 px, focus return, Esc); `supabase db reset`. Smoke test: `supabase start`, `supabase functions serve --env-file …`, sign up, create child, **Add device**, then `curl -X POST …/functions/v1/enrollment-redeem -H 'content-type: application/json' -d '{"code":"…","device_name":"curl"}'` once (201) and again (401), revoke from the UI.

- **Concurrency:** repository single-flight (`AtomicBoolean`, second call → `Busy`); UI flag blocks double-tap; redeem runs in an **application-lifetime scope** (`AppContainer.appScope`), not `viewModelScope`, so backing out cannot cancel a request the server already honoured — credentials are still saved and `AppStateHolder.refresh()` publishes the enrolled state.

## Decisions locked in Phase 17a
- **One migration** `20260930001600_screen_time_rules.sql`; no new table. `device_rules` gains `daily_limit_overrides jsonb` (`{}`; keys `"1"`–`"7"` = ISO weekday, integer 0–1440; a present key replaces the default for that weekday, `0` = no screen time, absent = default; `null` default + no override = no limit) and `config_version int` (starts 1). Neither column is granted to `authenticated` (SELECT only); the existing column grants are unchanged, so direct PATCHes of limit/bedtime/school still work **and are versioned** — overrides only change through the RPC.
- **Versioning lives in triggers, not in the RPC** (so every write path is consistent): BEFORE UPDATE `device_rules_config_version` bumps by exactly 1 iff daily limit / overrides / bedtime enabled+start+end / school mode really changed, otherwise restores the old value (clients cannot set or roll back the version). AFTER UPDATE `device_rules_config_changed` (when the version moved): queue one `SYNC_CONFIG` (payload `{}`, 24 h, ENROLLED devices only; **only PENDING dedupes** — a DELIVERED one may predate the change) and write `RULE_CHANGED` (`metadata.fields` = column names, never values; `ip_address` NULL) when `auth.uid()` owns the device. ## Decisions locked in Phase 17b
- **Web only:** no migration, Edge, Android, contracts or dependency change. - **Form model (decision):** no free JSON. Default: `off | limit(minutes) | zero`; each weekday: `default | limit(minutes) | zero`. Minutes = whole numbers 1…`DAILY_LIMIT_MAX_MINUTES` (no hours parsing, no `+`, `e`, decimals, full-width digits); the minutes box is read only when the mode is `limit` (so a disabled/hidden box can never leak a value). `0` exists only as "No screen time" (`zero`) and a stored default of 0 round-trips. `toFormValues ↔ parseRulesForm` round-trip is tested. `screenTimeRulesInputSchema` has the last word; the RPC/CHECKs are the final guard.
- **Outcome mapping:** `updated` → "Saved. The child's phone picks this up on its next sync."; `unchanged` → "No changes to save."; `not_found` → `notFound()` (404, same for foreign and missing); `inactive` → read-only notice; `22023` → generic limits message (values kept); `42501` → `/login`; anything else, including an empty/unknown RPC response → generic failure. Logging = `rules_save_failed` + error code only (tested against ids and values).
- **Page:** shows stored state first (`RulesCard`: version + "updated N ago", per-weekday effective limit, bedtime/school mode read-only), then the editor only for ENROLLED devices; REVOKED/PENDING get a one-line read-only note. `key={configVersion}` remounts the form when the stored version changes. No `AutoRefresh` here (it would fight an edit in progress). A missing rules row (should not happen — trigger creates it) renders "Rules not available".
- **Dashboard "Active restrictions":** counts ENROLLED devices with a default/override limit, bedtime or school mode; revoked/pending excluded; unreadable rules = *unknown* (never counted as unrestricted; all unknown → dash); `0` is a real 0. App rules (Phase 18) and schedules (Phase 19) are not counted yet. Hint ends "These are settings; the app can't lock a phone."

Guards ban secure/safe/protected and "guaranteed / cannot be bypassed / locked out".
- **Known limitations / unverified:** `.tsx` components were reviewed by hand only (no React/Next types here). Likeliest first-run fixes: `Label` from `components/ui/label` with `className`, native `<select>` focus ring classes, `aria-label` + `disabled` on `Input`, import-order lint in `queries.ts`/`rules.ts`, React 19 form reset vs. the controlled mode selects (modes are state, minutes are `defaultValue = state.values ?? initial`).
